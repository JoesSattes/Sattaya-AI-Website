Research · Preprint, 2026

Reading the Architecture off the Weights: Manifest-Only Model Anatomy and a Census of 12,974 Hugging Face Repositories

Sattaya Singkul (สัตยา สิงห์กุล), sole author

PDF ResearchGate Try AI Model Explorer Hub census Plain-language explainer

Abstract

Engineers who deploy a model need to understand its composition, including which blocks repeat, what each block computes, how the parts are connected and where the parameters reside. This information is usually distributed across model cards, family-specific configuration files and modeling code. We show that most of it can be read from the tensor manifest alone, the list of tensor names, shapes and storage types that a safetensors file stores in a header of a few tens of kilobytes. Our method normalizes quantized storage, finds repeated blocks in the module tree, assigns roles to the parts of each block from the algebra of their shapes, and links components by matching their widths. Fields that shapes cannot determine, such as the number of attention heads, are read from config.json when it exists, and the configuration is checked against the weights. On 510 architectures from the transformers library, with ground truth taken from module classes that the method never sees, the method assigns per-tensor roles with 96.8% accuracy, compared with 82.3% for the strongest name-rule baseline, and retains 95.0% accuracy when every name is replaced by a random token. Parameter counts are exact for every model, including under NVFP4, FP8 and GPTQ storage. On 191 popular Hugging Face checkpoints read over HTTP range requests, totals agree with the Hub's own count for 149 of 158 checkpoints, with most of the differences arising because the Hub counts packed 4-bit storage, and configuration fusion recovers head geometry for 96 to 98% of models. A census of 12,974 Hub repositories, read at a median cost of 80 KB each, finds that 28% of readable Hub models are distributed without a configuration file. Among popular original language models, the share of mixture-of-experts models rose from 0% (created up to 2022) to 42% (2026), and the KV cache per token per billion parameters fell 24-fold. Quantized copies make up 6% of repositories but receive 28% of downloads, 73% of fine-tunes keep their parent's architecture, and the parameter count reported by the Hub is incorrect for 89% of NVFP4 releases. The labeled corpus and the census are released as open datasets with every raw manifest. The method runs in about 10 ms for a typical model, and we release it as an open explorer that can analyze any Hugging Face repository without downloading its weights.

Highlights from the Hub census

  • Mixture-of-experts models rose from 0% of popular original language models created up to 2022 to 42% of 2026 releases.
  • KV cache per token per billion parameters fell 24-fold over the same period.
  • Quantized copies are 6% of repositories but receive 28% of downloads.
  • The Hub's displayed parameter count is wrong for 89% of NVFP4 releases.
  • 28% of readable Hub models ship without a config.json.

Code, data and tools

  • AI Model Explorer: the web app, in English and ภาษาไทย.
  • Python package and CLI: pip install ai-model-explorer (PyPI), with inspect, fits, diff, scan, census and ready.
  • Hub Weight Census page and the Deploy-Ready board, where anyone can submit a model.
  • Datasets on Hugging Face: hub-weight-census and manifest-anatomy-corpus, with every raw manifest.
  • Source code (MIT) and the checkpoint benchmark.

Who created this

Sattaya Singkul created the manifest-only recovery method and AI Model Explorer. The tool began with the workshop “Squeeze Until It Breaks: A Hands-On Edge Inference Contest” at AI Expo Thailand 2026, was then generalised to any architecture, evaluated in this paper and applied to a census of the Hugging Face Hub.
